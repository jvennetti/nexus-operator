# Front-end QA audit

Branch `worktree-agent-a061d163485207aba`, based on `claude/friendly-ramanujan-jrotfb` (1b725ba). That base has the video lessons, which the lesson and video checks needed. Every page type was tested in Chromium (Playwright 1.63) at **1280×900** and **390×844**, with seeded localStorage states:

- `fresh`: nothing set
- `firstHub`: intro seen, hub not yet visited
- `returning`: Pre-Course and Module 1 done, a last page and a note set
- `allDone`: every module done, machine not yet activated
- `finished`: every module done, machine activated

The audit runs on a fake page clock, so the long typewriter sequences finish fast. While a page runs, it samples every 100 ms (see "How to re-test").

**Result:** the baseline had 94 findings across 36 page runs. After the fixes there are 7 across 40 runs (4 runs were added for the not-yet-activated machine). None of the 7 is a glitch from the list: they are web-font swap reflow at load and the activation message feed. Both are covered under "Not changed". There were no console errors, page errors, failed internal requests, unhandled `play()` rejections or horizontal overflow at 390px, either before or after. `tools/qa/check_links.py` finds 0 unresolved `href`/`src`/asset paths.

## Not changed (and why)

- **ciro-intro line colours never apply.** `addLine('dim')`, `addLine('yellow')` and the other one-argument calls pass the class as the *text* argument, so the `dim`/`yellow`/`red`/`blue` styles in the CSS never reach the lines; only `small` works. Fixing this would change what the page looks like (colours and the red line's weight), so it's for the lead to decide. The size reservation copies today's actual behaviour.
- **Font-swap reflow at load** (CLS about 0.01–0.02 on the hub and vault, and up to 0.14 on the machine's final state). This comes from Google Fonts `display=swap`. Removing it means `display=block` or self-hosted, preloaded fonts, which is a loading and design decision. The audit reports it as a note.
- **The activation page's message feed** (`machine/activated.html`, `#vanta-text` and the CIRO paragraphs). It is a scrolling, chat-style feed that grows by design and auto-scrolls. `decryptInto` appends paragraphs to one element, so pre-laying it out would mean restructuring the sequence. What remains is per-word wrap jitter inside the feed.
- **"No music?" on the hub at phone width** overlaps the title. The hub has no nav, and every other free spot near the top covers the progress figure. Placing it is a design call.
- **localStorage with storage fully blocked.** Chrome Incognito, Firefox Private and Safari 11+ Private all provide working localStorage, so private mode doesn't break anything. Most top-level reads aren't wrapped in try/catch, so they do throw when site data is *blocked entirely*. In that case the course can't keep progress or intro state between pages anyway: the lesson guard sends you back to `index.html`. Wrapping every read would turn a broken page into an endlessly resetting one, so it was left alone.
- **`SCENE_W`/`TARGET_X` on the intros** are measured once, so CIRO's roll-in target is stale after a resize or rotation mid-animation. It is cosmetic and resolves on reload.
- **Unused `const container`** variables are left in the complete templates. They are harmless, and the diff stays small.
- **Hub `AudioContext` created at load** logs Chrome's autoplay warning. It is a warning, not an error, and the existing click/touch unlock handles it.

## How to re-test

```
python3 -m http.server 8791 --bind 127.0.0.1 &        # from the repo root
node tools/qa/audit.js [out.json] [--only=<url-substring>]
node tools/qa/double.js                                 # double-activation → 1 transition
python3 tools/qa/check_links.py                         # every href/src/asset path resolves
node tools/qa/snap.js <base> <page> <state> <outPrefix> desktop|phone 1000,5000[,…] [selector@ms]
python3 tools/qa/imgdiff.py before.png after.png        # pixel diff of two screenshots
```

- **`tools/qa/audit.js`** walks every page type at both viewports. For each page it reports: console and page errors, failed or 4xx internal requests, unhandled rejections, horizontal overflow, controls that are invisible but clickable or focusable (ignoring a control during its own fade-in), size or position changes of tracked boxes while text types, and Chrome `layout-shift` entries, with font swaps split out. It also runs these flows: clicking the not-yet-visible intro and complete buttons, clicking the hidden "continue anyway" link, the lesson soft-lock with Mark task done and reload, and the full ciro-intro dialogue through both phases.
- **`tools/qa/probe.js`** is the in-page instrumentation it injects.
- **For a before/after comparison**, serve `git archive <base>` from another port and pass `QA_BASE=http://127.0.0.1:<port>/`.
