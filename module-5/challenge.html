The Challenge
The Scenario

A skill, a handoff, a scheduled task. Separately they're features. Together they're the thing this whole course was pointing at: work that happens without you starting it, done the way you'd do it.

This challenge is one skill plus one scheduled task, running on your real life, by the end of the week.

Your Challenge
  1. 1
    Write a second skill. You wrote one in Lesson 5.1. Pick another recurring task from your task list. Do it manually once, then "turn that into a skill." You should now have a /skills folder with two tested skills.
  2. 2
    Make the skills portable. Ask Claude: "Review both skills. Make sure each one says when to use it, what it needs, the steps, the output format with an example, and the checks. Make them consistent with each other." Good skills read like a checklist a new hire could follow.
  3. 3
    Schedule one of them. Whichever would be most satisfying to find done in the morning. Manual run twice. Draft, don't send. Schedule it.
  4. 4
    Let it run three times. Each morning, review the output. Each correction goes into the skill. Log what changed.
  5. 5
    Make the trust decision. After three runs: does it still need to draft, or can it send? Does it still need your review, or can it run quietly? Change the task to match your honest answer. Write down what would need to be true to go further.
Your Deliverable
  • Two tested skills in your workspace, consistent in structure, each run cold at least once.
  • One scheduled task that has run three times on real input with corrections folded back into the skill.
  • A written trust decision: what it's now allowed to do on its own, and why.

If a connector or scheduling option doesn't exist for a tool you use, ask Claude how else to get the input in or the output out. A folder Claude Code watches, a shared doc, an email to yourself. There's always a route.
