## Brief

A few things about working in Claude Code day to day that nobody tells you until you've learned them the hard way.

**Sessions.** Each conversation in Claude Code is a session. Long sessions get slow and forgetful, exactly like long chats. The fix is the same: start a new session for a new task. Because the folder is the memory, you lose nothing. If you're mid-task and need to stop, say "write a short HANDOFF.md describing where we are and what's next" and the next session picks it up.

**Permissions.** Claude Code asks before it does things that could matter: changing files, running commands. Early on, read every prompt. Once you trust a kind of action ("edit files in this folder"), you can allow it going forward. Don't blanket-approve everything on day one. Earn your own trust.

**Undo.** Ask Claude to set up version history in your workspace ("set up git and commit after each change" is the sentence, and you don't need to know what it means). After that, anything can be rolled back with "undo the last change" or "take this file back to how it was this morning."

**Scope.** Claude Code only sees the folder you opened. That's a feature. Keep your workspace separate from the rest of your computer and you never have to worry about what it might touch.

**When it gets stuck.** It loops, it apologizes, it tries the same thing three times. Stop it. Start a new session. Describe the goal fresh, in one clean message. It almost always works the second time.

## Task

Set up the safety habits once so they're always there.

1. **Version history.** In your workspace: "Set up version history for this folder using git, and commit after each change you make from now on. Add that rule to CLAUDE.md." Approve the prompts.
2. **Test undo.** Make a change: "Add a line to README.md that says 'test line.'" Then: "Undo that last change." Confirm the line is gone.
3. **Practice the handoff.** Mid-way through any task, say: "Write a HANDOFF.md with where we are and what's next." Close the session. Open a new one. Say: "Read HANDOFF.md and continue." Watch it pick up.
4. **Review your permissions.** Look at what you've allowed. Keep what you understand. Revoke anything you don't remember approving.
5. **Write the escape hatch into CLAUDE.md:** "If you try the same fix twice and it fails, stop and tell me what you've tried instead of trying again."

## Takeaways

- New task, new session. The folder is the memory, so you lose nothing. Use a HANDOFF.md to stop mid-task.
- Read permission prompts early. Allow kinds of actions you've come to trust, not everything at once.
- Set up version history once. Then "undo the last change" always works.
- When it loops, stop it and start clean. The second attempt usually works.
