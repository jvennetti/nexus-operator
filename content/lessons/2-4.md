## Brief

Projects stop you re-explaining yourself in every new chat. A Project holds **instructions** (standing guidance for every chat inside it) and **knowledge** (files every chat inside it can see). Make one for anything you'll discuss more than three times.

## Task

Build one Project you'll keep using.

1. **Pick one area** that comes up constantly: a client, a team, a recurring responsibility. If nothing jumps out, use your job.
2. **Write the instructions with Claude.** New chat, paste this, answer the questions, then edit the result until it sounds like you:
```
I'm creating a Claude Project for [the area]. Interview me, one question at a time, until you can write a set of Project instructions that covers: who I am in this context, what the project is about, who the usual audience is, how I like things written, and three things you should always do and two you should never do. Then write the instructions.
```
3. **Create the Project** in the sidebar and paste the instructions in.
4. **Add two to four files** you'd otherwise attach every time: a brief, a template, an example of good output.
5. **Run one real task inside it** without explaining the background.

## Takeaways

- A Project holds instructions and files that every chat inside it can see.
- Instructions are for what's true every time. One-off material goes in the chat.
