## Brief

Everything until now needed you to start it. Scheduled tasks remove that step. You describe a task once, set when it should run, and Claude runs it on its own: every morning, every Monday, the first of the month. You wake up to the result.

This is where skills pay off. A scheduled task is only as good as the instructions behind it, and a skill is exactly that: tested, specific instructions for one task. Schedule a skill and you have a system that runs without you.

What people schedule first:

- **The morning briefing.** The thing you built in Module 3, run at 7am and waiting in your inbox.
- **The weekly report.** Pull from the task tool, format the way the skill says, send to the team.
- **The follow-up check.** Every day, find anything you sent that hasn't had a reply in three days and draft the nudge.
- **The monthly tidy.** Organize the downloads folder, archive finished projects, update the reference list.

Two rules for scheduling anything:

- **Run it manually first, at least twice.** If it doesn't produce what you want when you're watching, it won't when you're not.
- **Start with tasks that draft, not tasks that send.** A scheduled task that drafts the replies and leaves them for you is safe to get wrong. One that sends them isn't. Earn the trust in that order.

How to set one up: at the end of a task that went well, say "schedule this to run every [weekday at 7am]." Claude will confirm the details and set it up. Where scheduled tasks live and how to edit them is in the app, and Claude can show you.

## Task

Schedule something real and let it run.

1. **Pick the task.** Your morning briefing from Module 3, or the skill you wrote in 5.1. Whichever you'd most like to find already done tomorrow.
2. **Run it manually, twice.** Fix anything that's off. The second run should be exactly what you want.
3. **Make it draft, not send.** If the task involves emails or messages, make sure the instructions say to draft them, not send them. You'll relax this later.
4. **Schedule it.** "Schedule this to run every weekday at [time], and deliver the result to [where you'll see it]." Confirm.
5. **Check tomorrow.** When it runs, review the output. Note what you'd change, then tell Claude to update the task. In your notes below, record how it went.

## Takeaways

- A scheduled task runs on its own, on a cadence you set. You wake up to the result.
- Schedule skills, not vague prompts. Tested instructions produce consistent output.
- Run it manually twice before scheduling. Start with tasks that draft, not tasks that send.
