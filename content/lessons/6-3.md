## Brief

A system you built yesterday is a prototype. A system you've run for a week is real. This lesson is about the week.

Three things happen when you run a system on real input for several days:

- **Edge cases show up.** The email with no subject line. The report that's missing a section. The week with a holiday. Each one is a rule to add to the skill.
- **You notice what you still do by hand.** The one step you kept out of Version 1 because it seemed hard. The check you do before trusting the output. Those are the next version.
- **You learn whether you trust it.** This is the real question. By the end of the week you'll know whether this can send instead of draft, run without you reviewing, extend to a second input.

The habit that makes this work: **every time you correct the output, fix the skill.** Not the prompt, not the output by hand. The skill. Each correction is permanent. A system you've corrected ten times is a system that gets it right.

Keep a short log in your workspace. Date, what the system did, what you changed. By the end of the week it'll tell you exactly what Version 2 should be.

## Task

Run the system for a week and improve it as you go.

1. **Create the log.** In your workspace: "Create RUN-LOG.md with a table: date, what ran, what was wrong, what I changed." Ask Claude to add a line after every run.
2. **Run it every day** (or every time the input arrives). Review every output. For each problem: "Fix the skill so this doesn't happen again." Then log it.
3. **Add one thing you were doing by hand.** Mid-week, pick the step you kept out of Version 1 and ask Claude to build it in. Test it twice.
4. **Make the trust call.** End of week, ask yourself: can this send instead of draft? Can it run without my review? If yes to either, change it. If no, write down what would need to be true.
5. **Write Version 2.** "Read RUN-LOG.md and WORKFLOW.md. Propose Version 2: what to add, what to change, what to leave alone. Update WORKFLOW.md." Read it. Decide what to build next.

Mark done at the end of the week.

## Takeaways

- A system is real after a week of real input. Edge cases, hand steps, and trust all show up in the running.
- Every correction goes into the skill, never into the output by hand. Corrections are permanent.
- Keep a run log. It writes your Version 2 for you.
