## Brief

A system you built yesterday is a prototype. Run it on real input for a week and three things show up: edge cases, steps you still do by hand, and whether you trust it to send instead of draft.

The habit that makes it work: **every time you correct the output, fix the skill.** Not the prompt, not the output by hand. Each fix is permanent.

Keep a short run log. By the end of the week it tells you what Version 2 should be.

## Task

Run the system for a week and improve it as you go.

1. **Create the log.** "Create RUN-LOG.md with a table: date, what ran, what was wrong, what I changed. Add a line after every run."
2. **Run it every day.** Review every output. For each problem: "Fix the skill so this doesn't happen again."
3. **Build in one hand step.** Mid-week, add the step you left out of Version 1. Test it twice.
4. **Make the trust call.** Can it send instead of draft? Run without your review? If yes, change it. If no, note what would need to be true.
5. **Write Version 2.** "Read RUN-LOG.md and WORKFLOW.md. Propose Version 2: what to add, change and leave alone. Update WORKFLOW.md."

## Takeaways

- Every correction goes into the skill. Corrections are permanent.
- A week of real runs, logged, writes your Version 2.
