## Brief

Run it for a week, and make every fix stick. This video is about the mistake everyone makes: correcting the output and never the instructions, so the same error comes back. You'll keep a run log so it doesn't.

## Challenge

Run it for a week and log it.

1. In the **Code** tab, paste:
```
Create RUN-LOG.md. Then add a rule to CLAUDE.md: after every run, add one line to RUN-LOG.md with the date, what was wrong, and what changed. If the mistake is already listed, add a tick instead. Read RUN-LOG.md before every run.
```
2. Run your Version 1 on real work every day this week.
3. Each time you correct something, follow with:
```
Update the skill with that change so it doesn't happen again. Show me what changed.
```
4. Test one fix cold: new session, same kind of input, confirm the mistake is gone.
5. End of the week, paste this, then write "Version 2 does: ..." in WORKFLOW.md:
```
Read RUN-LOG.md. Which mistakes came back three or more times, and where should each fix live: the skill, CLAUDE.md, or the project instructions?
```

Mark this done when Version 2 is written.

## Takeaways

- Fix the instructions, not the output. Otherwise the same mistake comes back.
- A run log turns "I think it's better" into "here's what changed."
- Test fixes cold. "I'll remember that" means nothing in a new session.
- The trust call is yours: what Claude does alone, what it drafts, what stays with you.
