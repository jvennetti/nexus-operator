## Brief

This module is one project: pick one recurring piece of your work and build the system that runs it, on real data.

Pick something that:

- **recurs** daily or weekly,
- **has the same shape every time** (reports, summaries, follow-ups, triage),
- **costs you at least an hour a week.**

Then map it with four questions: **input** (what arrives, and where), **steps** (what happens to it), **output** (what comes out), **destination** (where it goes). Those four answers are the design. The rest is parts you already know: connectors, a skill, a scheduled task, Claude Code for files.

## Task

Pick and map the workflow you'll build.

1. **Choose from your Operator List** the item that best fits all three criteria. If torn, pick the one that annoys you most.
2. **Map it with Claude.** In your workspace:
```
I'm going to build a system that handles this workflow for me: [describe it in a few sentences]. Help me map it. Ask me questions until you can write a one-page WORKFLOW.md with four sections: Input (what arrives and where), Steps (what happens to it, in order), Output (what comes out and in what shape), and Destination (where it goes and who sees it). Then list which tools we'll need: which connectors, whether it needs a skill, whether it should be scheduled, and whether it needs Claude Code to handle files.
```
3. **Cut it down.** Remove any step you only do out of habit. Then add a line at the bottom: "Version 1 does: ..." Keep it to the simplest version that's still useful.

## Takeaways

- Pick work that recurs, has the same shape, and costs real time.
- Input, steps, output, destination. Build the simplest useful version first.
