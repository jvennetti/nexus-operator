## Brief

You have the map. Now you assemble.

The build order that works, nearly every time:

1. **Get the steps right by hand.** Run the workflow manually with Claude, on real input, until the output is exactly right. This is Module 2 all over again: brief, notes, iterate. Don't automate anything you haven't done right manually.
2. **Turn the steps into a skill.** "Turn what we just did into a skill." Now the process is written down and repeatable.
3. **Wire the input and destination.** Connectors for the tools involved. If the input is files, Claude Code reads the folder. If the destination is a sheet or a task tool, the connector writes to it. Test each connection with one real item.
4. **Run the whole thing end to end, manually, twice.** Input to destination, with you watching. Fix what breaks. Fix the skill, not the prompt.
5. **Only then, schedule it** (if it should run on a schedule) or write down the one sentence that triggers it (if it runs on demand).

Resist the urge to build the full version. Build Version 1 from your WORKFLOW.md. A small system that works beats a big one that almost does.

When you hit something you don't know how to do, you already have the move: describe what you want to Claude and let it figure out the how. "I need this to end up in a Google Sheet with one row per item. How do we do that?" That question is the whole technical skill.

## Challenge

Build Version 1, end to end.

1. **Manual run.** In your workspace, with WORKFLOW.md open: "Read WORKFLOW.md. Let's do Version 1 manually, together, step by step, on this real input: [attach or point to it]." Give notes until the output is right.
2. **Make the skill.** "Turn that into a skill in /skills, with the output format and an example. Reference WORKFLOW.md."
3. **Connect the ends.** Make sure the connectors for input and destination are live. Test: "Pull one real item from [input] and process it with the skill, then put the result in [destination]. Show me before you write anything." Approve. Check the destination tool yourself.
4. **Two full runs.** Run the entire workflow twice on real input, watching. Fix anything off by editing the skill.
5. **Decide the trigger.** If it should run on a schedule, schedule it (drafting, not sending, for now). If on demand, write the trigger sentence into WORKFLOW.md: "To run: say '...'"

Mark done when Version 1 has completed two real runs.

## Takeaways

- Get it right by hand before automating. Then: skill, connect the ends, two full test runs, then trigger.
- Build Version 1 from the spec. Small and working beats big and almost.
- When you don't know how: describe the outcome and ask Claude how. That's the technical skill.
