## Brief

You've heard the word. Here's what it means: **a skill is a text file with instructions for one specific task.**

That's the whole definition. There's no software. A skill is a document that says: when I ask you to do X, here's how I want it done, here's what good looks like, here's what to check before you're finished. Claude reads it when the task comes up and follows it.

You already wrote one, sort of. `CLAUDE.md` is the general version: how to work with you across everything. A skill is the specific version: how to do *this one thing.* The weekly report. The client proposal. The meeting summary. The invoice follow-up.

Why this matters more than it sounds: every time you've explained a recurring task to Claude from scratch, you've paid a tax. A skill is paying it once. After that, "do the weekly report" is the entire prompt, and the output is consistent every time, because the instructions didn't change.

What a good skill contains:

- **When to use it.** "Use this when I ask for a weekly status report."
- **The inputs.** "Read the task list from ClickUp and my notes in /weekly."
- **The steps.** The actual process, in order.
- **The output format.** Exactly what the result looks like. Include an example.
- **The checks.** "Before finishing, confirm every open item has an owner and a date."

The fastest way to write one: do the task once with Claude, manually, the way you want it. Then say "turn what we just did into a skill." It writes the file from the actual process.

## Challenge

Write your first skill from a task you already do.

1. **Pick a recurring task** from your Operator List. Something you do weekly or more. A report, a summary, a message you send in the same shape every time.
2. **Do it once, manually, with Claude.** In your workspace, walk through the task step by step, giving notes until the result is exactly what you'd want every time.
3. **Turn it into a skill.** Say: "Turn what we just did into a skill file in a /skills folder. Include when to use it, what inputs to read, the steps, the exact output format with an example, and what to check before finishing. Then add a line to CLAUDE.md that says to use skills from /skills when a matching task comes up."
4. **Read the skill file.** Edit anything that's not how you'd describe it.
5. **Run it cold.** New session. Say only: "Do the [task name]." Nothing else. Compare the output to the manual run. If something's off, fix the skill, not the prompt.

## Takeaways

- A skill is a text file with instructions for one specific task. No software involved.
- `CLAUDE.md` is the general version. Skills are the specific versions, one per recurring task.
- Fastest way to write one: do the task manually once, then say "turn that into a skill."
- When the output is off, fix the skill, not the prompt.
